1. INTRODUCTION                                                 *dbgrid-intro*

dbgrid turns a plain `.sql` file into a notebook: every line starting with
`-- %%` begins a cell. The notebook opens in its own tabpage with the cells
on one side and a results pane on the other. Moving the cursor into a cell
shows that cell's last result from the cache; nothing is re-run.

Notebooks are stored per project (git root of the current directory) and
carry tags, so `:Dbgrid` and `:Dbgrid tags` find them again.

Requires Neovim 0.10+ and `psql` on PATH.

==============================================================================
2. SETUP                                                        *dbgrid-setup*

>lua
  require("dbgrid").setup({
    connections = {
      { name = "local", url = "postgres://localhost/app_development" },
      { name = "prod", url = "$PROD_URL", readonly = true, index_check = "confirm" },
    },
    layout = { results = "left", size = 0.5, tab = true },
    query = { limit = 500, confirm_writes = true },
    index_check = { mode = "warn", min_rows = 10000 },
    ai = { agent = "claude" },
  })
<
Connections are also discovered from `DATABASE_URL` (and `DB_URL`,
`POSTGRES_URL`, `PG_URL`) in the environment and in `.env` files of the
project, and saved interactively with `:Dbgrid connections`.

Storage: `storage.mode` is "auto" (use `<root>/.dbgrid` when it exists, else
the data directory), "project" or "data". Result caches keep
`storage.cache_rows` rows per cell.

See `lua/dbgrid/config.lua` for every default, including all keymaps.

3. NOTEBOOK FORMAT                                             *dbgrid-format*

>sql
  -- %% [k3x9] overdue invoices
  -- ? invoices unpaid for more than 30 days
  -- @nolimit
  select ...
<
`-- %% [id] title`   starts a cell; the id is generated and concealed.
`-- ? text`          prompt for the agent (|dbgrid-ai|).
`-- @nolimit`        do not add the automatic LIMIT.
`-- @notx`           do not wrap a multi-statement cell in a transaction.
`-- @conn name`      run this cell on another connection.
`-- @dryrun`         run a write with RETURNING * and roll it back.
`-- @every 5s`       re-run the cell on that interval (|dbgrid-params|).
`-- @param n = 3`    default for the `:n` parameter (|dbgrid-params|).

4. COMMANDS                                                  *dbgrid-commands*

:Dbgrid open [name]            open a notebook

:Dbgrid run [all]              run the current cell or all cells
:Dbgrid explain [analyze]      plan of the current cell
:Dbgrid ask {prompt}           add a prompt to the cell and generate SQL
:Dbgrid schema refresh|tables  refresh the schema cache / browse tables
:Dbgrid describe {table}       describe a table
:Dbgrid rename {title}         rename the notebook
:Dbgrid delete                 delete the notebook
:Dbgrid close                  close the notebook layout
:Dbgrid export csv|json|md [path]
                               current result (md: the notebook) to the
                               register or a file
:Dbgrid cancel                 stop the running query, generation or live loop
:Dbgrid health                 same as `:checkhealth dbgrid`
:Dbgrid new --template {name} [title]
                               create a notebook from a template
:Dbgrid templates              pick a template (`templates list` prints them)
:Dbgrid analyze                agent analysis of the cell's plan
:Dbgrid explain-error          agent explanation of the cell's last error
:Dbgrid try-index [sql]        hypothetical index (hypopg), cost before/after
:Dbgrid params [name value]    re-prompt / set parameters; `params clear`
:Dbgrid live [interval|stop]   start or stop the live loop of the cell
:Dbgrid diff [connection]      diff against the previous run, or against the
                               same cell run on another connection
:Dbgrid schema diff [a] [b]    compare two schemas
:Dbgrid settings diff [a] [b]  compare pg_settings of two connections
:Dbgrid history                pick a statement from the project history
:Dbgrid aws {sub} [connection] add | login | refresh | tunnels | status |
                               events | bluegreen (|dbgrid-aws|)

5. KEYMAPS                                                    *dbgrid-keymaps*

Buffer-local, configurable through `keymaps.query` and `keymaps.results`
(set an entry to `false` to skip it). `\` stands for <localleader>.

Query pane ~
  <CR> \r     run the cell           \R          run all cells
  \e  \E      explain / analyze      \x          cancel
  ]c  [c      next / previous cell   ]C  [C      last / first cell
  \n \o \O    new cell end/below/above
  \d          delete cell            \y          yank cell
  \m          rename cell            \g          generate SQL from prompt
  \a          analyze plan (agent)   \A          explain error (agent)
  \i          try suggested index    \P          re-prompt parameters
  \H          query history
  \t          edit tags              \c          pick connection
  \s  \S      refresh schema / browse tables
  K           describe identifier    \<Tab>      focus results
  \z          zoom pane              \q          close notebook
  ic  ac      text objects (inner cell / whole cell)

Results pane ~
  <CR> K      inspect value          \v          record view
  \p          plan view              \w          toggle truncation
  \s          sort by column         \f          filter rows
  \d          diff vs previous run   \h          sparkline (live cells)
  \yc \yr \ya \yi \yp   yank value / row JSON / CSV / row INSERT / plan
  <Tab> <S-Tab>     next / previous column (row in record view)
  ]c  [c      next / previous cell   \<Tab>      focus query pane
  \z          zoom pane              q           close notebook

6. RUNNING QUERIES                                                *dbgrid-run*

Each run spawns `psql -f -` with the statements of the cell. Multi-statement
cells run in one transaction unless they contain BEGIN or `-- @notx`.

LIMIT           read-only statements without a top-level LIMIT/FETCH get
                `LIMIT {query.limit}`; the footer reports when it was hit.
Writes          INSERT/UPDATE/DELETE/MERGE/DDL/DO/CALL ask for confirmation
                (`query.confirm_writes`); UPDATE/DELETE without WHERE get a
                louder prompt. The prompt counts the rows an UPDATE/DELETE
                touches (`query.preview_writes`). `readonly` connections
                reject writes.
Dry run         `-- @dryrun` or `query.dry_run`: the write runs with
                RETURNING * inside a transaction that is rolled back, also
                on read-only connections.
DDL warnings    CREATE/DROP INDEX without CONCURRENTLY on a big table,
                ALTER TABLE (type changes, SET NOT NULL, constraints without
                NOT VALID, volatile defaults), TRUNCATE, VACUUM FULL,
                CLUSTER, REINDEX and a missing `lock_timeout_ms` are listed
                in the confirmation (`query.ddl_warnings`).
Session         `query.session = true` (or `session = true` per connection)
                keeps one psql alive across runs: temp tables and SET carry
                over and the connection handshake is paid once. Cancelling
                ends the session; the next run starts a new one.
Index check     `index_check.mode`: "warn" (default), "confirm" or "off".
                Statements are EXPLAINed first; a Seq Scan on a table with at
                least `index_check.min_rows` rows, or an Index Scan with a
                Filter but no Index Cond, produces a warning with a suggested
                `CREATE INDEX`. Plans are kept with the result.
Errors          shown in the results pane and as a diagnostic on the
                offending line of the cell.

7. PROMPT TO SQL                                                   *dbgrid-ai*

Write `-- ? what you want` in a cell and press <CR> (cell without SQL) or
`\g`. The prompt, the relevant tables of the schema, enum types and the
other cells are sent to the agent named by `ai.agent`. The answer replaces
the SQL under the prompt lines and the cell is marked "generated, not run".
When the cell already has SQL the prompt is an edit request.

Agents (`ai.agents`) are argv lists; `{prompt}` and `{output}` are
substituted, `stdin = true` pipes the prompt. Defaults exist for `claude`,
`kimi` and `codex`; add your own the same way.

==============================================================================
8. PLAN ANALYSIS                                              *dbgrid-analyze*

`\a` (`:Dbgrid analyze`) runs EXPLAIN (ANALYZE, BUFFERS, SETTINGS, FORMAT
JSON) on the cell inside a rolled back transaction (`ai.analyze.mode =
"estimate"` skips ANALYZE; writes ask first), gathers the tables' columns,
indexes and pg_stat_user_tables counters, applies the `analyze_rules`
(estimate off by `estimate_ratio`, sorts/hashes spilling to disk, the node
with the highest exclusive time, filters discarding most rows) and asks the
agent for: what is slow, why, the fix as SQL, what to verify. The answer
opens in a markdown window: `i` inserts its sql blocks as cells below the
analyzed cell, `y` yanks, `q` closes. It is kept with the result and shown in
the plan view (`\p`), which also renders actual times and buffers.

`\A` explains the cell's last error the same way. `\i` needs the hypopg
extension: the suggested index is created hypothetically in the same
session, the statement is re-explained and the cost before and after shown.

`ai.redact_literals` replaces literals before anything leaves the machine;
`ai = false` on a connection disables the agent for it; `ai.investigate`
gives the agent a read-only `dbgrid-query` shell helper on the connection.

==============================================================================
9. TEMPLATES                                                *dbgrid-templates*

`:Dbgrid new --template diagnostics` and `:Dbgrid new --template blue-green`
copy a bundled notebook into the project. Diagnostics: active queries,
blocking tree, idle in transaction, long transactions, top statements
(pg_stat_statements), seq scans, dead tuples, unused and redundant indexes,
cache hit ratio, sizes, connections, wraparound, temp files, replica lag,
replication, settings, extensions, locks on a table, cancel a backend.
Blue-green: slot lag, sender and subscription state, writes in flight, rows
written, application sessions, long transactions, tables without replica
identity, row counts and sequences on both sides, green accepts writes, make
blue read-only. Cells with `-- @conn blue|green` are bound to the
connections you pick. `templates.dir` adds your own (header lines
`-- template-name:`, `-- template-tags:`, `-- template-description:`,
`-- template-connections:`).

==============================================================================
10. PARAMETERS AND LIVE CELLS                                  *dbgrid-params*

`:name` in a statement is a parameter. Its value comes from `-- @param name
= value` in the cell, else from the notebook's remembered values, else from
a prompt (remembered afterwards). Values are inserted verbatim: quote
literals, leave identifiers bare. `\P` re-prompts, `:Dbgrid params name
value` sets, `:Dbgrid params clear` forgets.

`-- @every 5s` (`500ms`, `2m`) makes a read-only cell live: running it once
keeps it re-running until `\x`, an edit, an error or closing the notebook.
Ticks are skipped while one is in flight; changed values are highlighted
(|hl-DbgridChanged|); `\h` draws a sparkline of the numeric column under the
cursor over the last `live.history` ticks; `live.max_cells` caps the loops
per notebook. Live results are written to the cache when the loop stops.

==============================================================================
11. DIFFS, HISTORY, EXPORT                                       *dbgrid-diff*

`\d` diffs the current result against the previous run of the cell, matched
by the table's primary key (or an `id` column, or whole rows).
`:Dbgrid diff {connection}` runs the cell on another connection and diffs.
`:Dbgrid schema diff a b` and `:Dbgrid settings diff a b` open a scratch
buffer (`]c` / `[c` jump between tables, `q` closes).

Every statement is appended to `<store>/history.jsonl` (`history.enabled`,
`history.max_entries`); `\H` / `:Dbgrid history` inserts an entry as a new
cell, <C-y> yanks it. `:Dbgrid export md [path]` writes the notebook as
markdown with SQL, results and analyses.

12. AWS RDS AND TUNNELS                                           *dbgrid-aws*

>lua
  { name = "prod", aws = { profile = "prod", region = "ap-southeast-1",
      cluster = "app-prod", bastion = "i-0123456789abcdef0",
      secret = "prod/db",
      login_cmd = { "company-aws-login", "--profile", "{profile}" } } }
<
The entry appears as `prod/writer` and `prod/reader` (readers are
read-only; plain RDS gets one reader per replica). On the first run the
endpoints are resolved with the aws CLI and cached (`aws.endpoint_ttl_seconds`),
an SSM port forward to the bastion is started and kept for the session,
the password comes from Secrets Manager (or `auth = "iam"`) and goes to psql
through the environment. The URL keeps the real host with `hostaddr=127.0.0.1`
so `ssl = "verify-full"` with `sslrootcert` and ~/.pgpass work. Expired
credentials run `aws.login_cmd` (`{profile}` substituted) in a terminal
split and retry. Without `bastion` the connection is direct; `aws.document`
and `aws.parameters` cover custom SSM documents.

`:Dbgrid aws add` builds an entry interactively; `aws login`, `aws refresh`,
`aws tunnels`, `aws status` (status, version, maintenance, five CloudWatch
metrics), `aws events` (last day), `aws bluegreen` (deployments and
switchover status). `:checkhealth dbgrid` covers the CLI, the Session
Manager plugin, credentials and tunnels.

Generic tunnels: `tunnel = { kind = "ssh", host = "bastion" }` (remote
defaults to the URL's host:port) or `tunnel = { kind = "cmd", cmd = { ...,
"{port}" } }`; `local_port` fixes the local port.

13. COMPLETION                                             *dbgrid-completion*

blink.cmp: add a provider `{ name = "dbgrid", module = "dbgrid.completion.blink" }`
and "dbgrid" to `sources.default`.
nvim-cmp: `require("cmp").register_source("dbgrid", require("dbgrid.completion.cmp").new())`.
Omnifunc: set on notebook buffers by default (`completion.omnifunc`).

Items come from the schema cache: columns of the tables in the current
statement first, alias-qualified columns after `alias.`, then tables,
schemas, keywords and functions. `K` describes the identifier under the
cursor.

14. ADAPTERS                                                 *dbgrid-adapters*

`require("dbgrid").register_adapter(adapter)` adds a database. See
`lua/dbgrid/adapters/postgres.lua` for the reference implementation and the
README for the interface (`run`, `explain`, `explain_text`, `explain_json`,
`schema`, `test`, `cancel`, `keywords`, `functions`).
